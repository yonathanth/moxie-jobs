# Gursha Jobs (repo: ethio-jobs): working notes for Claude

Telegram-first job aggregator for Ethiopia, branded **Gursha Jobs** (GoMoxie logo; product name in `APP_NAME`, `lib/config.ts`; server and pm2 names keep the old moxie-jobs prefix). Users set preferences in a Mini App and get matching jobs as bot messages. CVs (create / improve / tailor to a job) are made by GoMoxie's engine (`../resume-back`, `routes/partner.routes.ts`, header `x-partner-key`, `PARTNER_API_KEYS` there; `GOMOXIE_API_URL` + `GOMOXIE_PARTNER_KEY` here). Ethio Jobs owns users, saved CVs (`CvDocument`) and billing.

## Database safety (read first)

`DATABASE_URL`/`DIRECT_URL` in `.env` point at a real Neon database.
- Never run `prisma migrate dev`, `migrate reset`, `db push`, `db execute`, or raw SQL that writes. Never pass a DB URL as `--shadow-database-url`.
- New migration: change `schema.prisma`, then `pnpm --filter @ethio/db migrate:diff` (offline, diffs against the last committed schema) → save into `prisma/migrations/<YYYYMMDDHHMMSS>_<name>/migration.sql` → review → apply with `pnpm db:migrate:deploy`. Ask the user before applying.
- Safe anytime: `prisma generate`, `prisma validate`, `pnpm db:migrate:status`, `pnpm db:seed` (idempotent upserts, never deletes).
- Don't create/modify rows for testing; use unit tests.

## Layout

- `packages/shared`: enums (education, experience, employment types), cities, plan limits, the preferences Zod schema, API DTO types. Built to CJS `dist/`, so rebuild after edits (`turbo` does this for dev/build).
- `packages/db`: Prisma schema, migrations, taxonomy seed (`prisma/seed-data/taxonomy.ts`: job functions → professions with aliases incl. Amharic; fields of study). Taxonomy ids are stable slugs: never rename or reuse one.
- `apps/api`: NestJS. Modules: config (Zod-validated env), auth (Telegram Mini App initData → JWT; dev login gated by `ALLOW_DEV_AUTH`), users (`/me`), taxonomy (`/taxonomy`), preferences (`/me/preferences`), settings (admin `Setting` rows: `betaAllPro`, `planLimits`, `prices`, `delivery`), billing (SantimPay hosted checkout: `POST /billing/checkout`, webhook `/billing/santimpay/notify`; a payment is only activated after SantimPay's signed status API says COMPLETED. Mirrors SantimPay Node SDK 2.0 (production-only): status checks send `fullParams`, callbacks' `signed-token` header is verified with SantimPay's public key (unsigned ones only get a throttled status check), and in production pending payments are reconciled every 2 min in case a callback is missed), bot (grammY; polling in dev, webhook `/telegram/webhook` in prod; job alert cards (worker `delivery/card.ts`) carry requirements in the text but not how to apply (that is on the Mini App job page and in the See details reply), and two buttons: See details (Mini App job page) | More jobs (For you feed); on http they fall back to callbacks `ap:<deliveryId>` / `mj`), jobs (`GET /jobs` feed, `GET /jobs/:id`; premium jobs redacted server-side for plans without them), health.
- `apps/worker`: plain TS process. Telegram listener (GramJS user account, `src/telegram`) → RawPost queue in Postgres → pipeline (`src/pipeline`: prefilter, enrich, Gemini extraction in `src/ai`, normalize, dedup/merge) → Job. Website sources (`src/web`, `Source.kind = "website"`: ReliefWeb API needing `RELIEFWEB_APPNAME`, African Union sitemap) feed the same RawPost queue. Delivery (`src/delivery`) matches new jobs to users and backfills a user's top open matches after each preferences save. Scripts: `tg:login` (one-time, interactive), `sources` (list/search/join channels), `extract:try` (run extraction on a text file). Spec: `docs/ingestion-spec.md`.
- `apps/web`: Next.js. `/` public landing; `/app` Mini App (overview, `/app/jobs` feed: For you / All jobs, search, URL-kept filters, keyset pagination + window virtualization capped at 300 items; `/app/jobs/[id]`; `/app/onboarding`, `/app/preferences`, `/app/plans`). Plan limits are enforced in the UI with `usePaywall().gate(reason, { then? })` (components/paywall.tsx): one sheet everywhere (plans that lift the limit with "from" monthly price → monthly / 3 months → SantimPay → on payment it refreshes /me and all queries and returns the user where they were, or to `then`). Upgrade prompts open the paywall, never link to `/app/plans` (only the Profile plan card and CV packs go there); `/billing/return` is public (SantimPay redirects there outside Telegram). Look matches gomoxie.app (`../resume`): light only, tokens in `globals.css`, Geist, lucide icons, near-black primary buttons, orange accent used sparingly.

## Conventions

- Paywall (product rule): following jobs is generous on every plan (free: 3 whole categories + 10 roles), because jobs are scarce. Plans differ on alerts per day, premium jobs and CVs. Prices 199/month Pro, 299/month Career (3 months 499/749); weekly plans aren't sold (`SOLD_PERIODS`). Free users' "For you" page 1 pins up to two locked premium matches at positions 1 and 3 (`pinAt`).
- Onboarding is one step (kinds of jobs); the rest is optional in Profile → Matching on. In the picker, tapping a category follows all of it (the default). Its chevron opens "Select all in this category" and then the roles. When the category is followed, every role is ticked, and unticking one leaves it out (`UserPreferences.excludedProfessionIds`, which never uses role slots; matching skips those roles even when the degree matches). When it isn't followed, picking roles follows just those roles.
- Plans: free / pro / career. Limits come from `resolveLimits(effectivePlan(user, settings), settings)` and prices from `resolvePrices(settings)`, never hardcoded. Every plan gets instant alerts; free has `dailyJobCap` 5 and no `premiumJobs` (NGO, UN/AU/embassy, foreign company, overseas; see `isPremiumJob`). Free-plan previews (`@ethio/shared` `previews.ts`, sent by the worker sender): matches after the 5th of the day get a text preview "New match: <title>" (Delivery skipped/daily_cap with the message id). Both previews read: "New match: <title>", blank line, one sentence (`previewSentence`: "A company is hiring a part-time remote <title> to <Job.roleBrief>.", or "An NGO is looking for a <title>." when there is no brief), blank line, place · apply by · salary, blank line, then one link ("Subscribe to Pro", t.me `?startapp=plans`) and one button (Get Pro to see details). Never the employer, requirements, experience, education or how to apply. Who is hiring is named by kind (`hirerPhrase`): An NGO / An international organization / An embassy / An international company / An employer in <country> / A government office / A company; never "UN" or "AU" (we only know the kind). `Job.roleBrief` is extracted by Gemini (`role_brief`, a verb phrase, no employer or requirements; newer jobs only). In the Mini App they are locked (`JobCardDto.lockReason = "daily_limit"`) until tomorrow in Addis Ababa, and opening one prompts "See it now with Pro / I'll see it tomorrow". "For you" keeps today's held matches out of the list: page 1 returns `held: { count, items }`, shown as one "N more matches today" row (expands to the locked cards; See them now opens the paywall). For you and All jobs have a label above each day (Today / Yesterday / Mon 24 Nov; For you by `matchedAt`, All jobs by posting day). Matches of kinds the plan lacks are queued `pending` + mode `locked` and sent at once as a picture preview with the same text ending "<Kind> jobs are for Pro members." (the specific kind: NGO / International organization / Embassy / International company jobs, Jobs abroad) (`/og/msg/premium?job=`, then status `teased`); the backfill previews at most 3 and stores the rest `locked`. Upgrading unlocks locked/teased rows through the backfill. Every morning (`settings.delivery.digestHourEat`, default 8 EAT) worker `delivery/digest.ts` sends free users one picture (`/og/msg/missed?n=`) listing up to 10 of yesterday's missed jobs (title · company, or the kind of employer for locked kinds) with See jobs | Get Pro. Preview texts also carry t.me deep links (`?startapp=plans` / `job_<id>` / `jobs`; the worker needs `TELEGRAM_BOT_USERNAME`). Beta = everyone Pro (`betaAllPro`, default true).
- Icons (user rule): never use lucide `Sparkles`, and never put emoji in the web/Mini App interface (headings, buttons, labels, empty states). Use lucide icons instead; job categories use `components/categoryIcons.tsx`, not the taxonomy `emoji` field.
- Delivery timing: the catch-up after saving preferences (Delivery `mode: backfill`) is sent in full and never counts toward the free daily limit (only new-job alerts do). People who open the Mini App from a link without starting the bot can't get alerts ("chat not found"), so the Mini App requires "Allow messages" (`components/miniapp/AlertsGate.tsx`). Onboarding asks before saving, and set-up users are blocked by a dialog until they allow. The check: `allows_write_to_pm` in the launch data, else `GET /me/messaging` (a sendChatAction probe). On allow, `POST /me/messaging/allowed`, the bot's `write_access_allowed` message, or /start from a set-up user touches their preferences, so the backfill re-sends deliveries that failed with `chat_not_found` (the worker's `ChatNotFoundError`). "For you" shows matches as soon as they're queued (pending/sending/chat_not_found too), and while the worker hasn't matched the latest save (`UserPreferences.matchedAt` < `updatedAt`, at most 2 min; BackfillWatcher checks every 5 s) the feed returns `matching: true` and the page shows "Finding jobs that match you" and polls. New-job alerts respect quiet hours (settings.delivery.quietFromEat/quietToEat, default 22→7 EAT) via `sendTimeAfterQuiet`; backfills (user just acted) send immediately. Users who never finish setup get one reminder (worker `OnboardingNudge`, `User.onboardingNudgedAt`). Optional salary preference (`UserPreferences.salaryMin/Max`, monthly ETB) only skips jobs that state lower pay (`monthlySalaryEtb`).
- Marketing (worker `delivery/promo.ts`, copy in `@ethio/shared` `promos.ts`, pictures from the web app `app/og/msg/[kind]`): one picture message per user in each slot (`settings.marketing.slotsEat`, default 12:30 and 19:00 EAT; `PromoLog` = one row per user per slot). Free: premium match (backfill leftovers still `locked`) → upgrade / make+tailor CV / CV packs taking turns (no alert-limit picture: each held job gets its own preview). Paid: renewal 2 days before, "ended" once, packs when out of CVs. Never in the first day, paused, blocked, before setup, quiet hours or the beta. Welcome, setup reminder, all set, plan activated and shared-job replies also carry pictures (`MOMENT_IMAGES`; `BotService.sendPhoto` / worker `sendPhoto` upload the card and cache Telegram file ids). Admin → Broadcast (`/app/admin/broadcast`, `AdminBroadcastService`) sends upgrade / CV / packs / setup / a chosen premium job by hand to free, paid, everyone, never-made-a-CV or not-set-up people (never blocked or paused), or a test to yourself; logged in PromoLog. Moxie on the cards is `lib/og/moxie-happy.ts` (GoMoxie`s art with glasses, a folder of CVs and a big smile, looking at you). The bot sets its description / short description on start (`BOT_DESCRIPTION`); its BotFather description picture and profile photo are `brand/bot-intro-640x360.jpg` and `brand/bot-profile-640.png` (from `/og/msg/intro` and `/og/msg/avatar`: "Gursha Jobs" big on one line, then "with Moxie" small with a small Moxie at its right). Picture links Telegram fetches or we upload carry `?v=CARD_VERSION` (`versionedCardUrl`, `@ethio/shared` promos.ts): Telegram keeps a picture by its exact link, so bump it whenever the pictures change. Mini App upgrade pop-ups: `components/UpgradeNudges.tsx` (5 s after a main tab loads, once per open, 8 h apart; local dev `/app?as=free&sent=10&waiting=4` shows them, display only). Profile → Share Gursha Jobs (`components/ShareAppCard.tsx`, `POST /share/app`): general / jobs / create CV / improve CV / premium jobs, each a picture message whose button is `t.me/<bot>?startapp=<kind>`, routed by `START_APP_ROUTES` (CV tab opens its modal from `?new=create|improve`). Admins: `/preview` in the bot (or `pnpm --filter @ethio/api preview:messages`) sends one of each.
- Wording (user rule): never say "premium jobs" to users (Mini App, bot, pictures). Name them: "NGO, embassy and international jobs" ("premium" stays only in code and admin screens).
- Bot copy has no emoji (same rule as the UI), with one user-approved exception: the wave (👋) on the first-time welcome greeting.
- Admin (Mini App → Admin, `/app/admin`, Telegram IDs in `ADMIN_TELEGRAM_IDS`; API `admin` module): review queue (approve → job active + flag `reviewed`, worker `ReviewWatcher` alerts if within `maxJobAgeHours`; reject → hidden), sources (stats, on/off, trust/priority, add by @handle → worker `JoinWatcher` joins one every 3 min; failures switch the source off with a note), prices & plan limits, beta, unpaid jobs (label | exclude), alert timing. Settings are Setting rows written with full values.
- Validation: Zod everywhere (`ZodValidationPipe` in the API); taxonomy/plan checks in `preferences.rules.ts` (pure, unit-tested).
- CVs (API `cv` module, rules in `cv.rules.ts`): charge order = free base CV (started from a job, never had a CV) → one free tailoring for everyone → plan allowance (`cvNewPerMonth`/`cvTailorPerMonth`, rolling 30 days, null = unlimited with `CV_FAIR_USE_PER_MONTH`) → a CV pack credit (`User.cvNewCredits`/`cvTailorCredits`, never expire; spent only once the CV exists) → `locked` (made now, watermarked PDF) up to `unpaidCvCap`. CVs aren't sold one by one: packs (`CV_PACKS`, Starter 99 / Job hunt 199 / All in 349 Br, prices in settings `cvPackPrices`) via `POST /billing/packs/checkout` (with `cvId`, a credit unlocks that CV on payment); `POST /cv/:id/unlock` spends an existing credit. Locked CVs the plan covers are unlocked from its allowance (`planUnlocks`, `CvService.unlockWithPlan`) right after a plan payment and whenever the CV list or a CV loads. Deleting is a soft delete (`deletedAt`) so usage can't be reset. PDFs go to the chat via `BotService.sendDocument`. The CV page has one Download button (`POST /cv/:id/send`, refused for locked CVs: no watermarked previews are sent). A locked CV downloads by unlocking it (a credit, or a CV pack). After that, a success dialog says the PDF is in the chat and offers Open the chat / the job or the feed / Keep editing. New CVs from the CV tab open `components/cv/NewCvModal.tsx` (GoMoxie-style centered modal: [details, first time] → write, or for Improve: upload a file / choose one of my CVs (`baseCvId`, the API reads it) → Moxie → the CV). Template pictures are GoMoxie`s small cached `thumb.webp`, preloaded when the editor opens; tailoring from a job opens `components/cv/TailorCvModal.tsx` on the job page (same modal: [details] → which CV / make a new one → write or upload → Moxie makes it and tailors it; mismatch and CV packs inside the modal; `?cv=1` opens it, old `/app/cvs/new?mode=tailor` links redirect there). Shared flow pieces (Working/Moxie, PriceNote, PackPrompt) live in `components/cv/flow.tsx`. Mini App tabs: Jobs | CV | Plans | Profile (`/app`). Job page: one bottom button (View on <source>), Requirements (`Job.requirements`, extracted; older jobs fall back to education/experience/skills) and How to apply sections, and a "Get a custom-made CV for this job" pill under the title.
- CV editor saves automatically (900 ms after typing stops). The top bar shows a Saved / Saving / Save chip (`SaveChip`; Save appears while changes are waiting or after a failed save).
- Amharic (user rule): until it's supported, preference screens show no Amharic text or hints (search aliases may stay; they're invisible).
- CV score: `apps/web/src/lib/cv-score/engine.ts` is a verbatim copy of GoMoxie's engine (`../resume/src/lib/cv-score/engine.ts`); never edit it here, re-copy it. Job match uses requirements fetched at tailoring time (stored in `CvDocument.jobAnalysis.requirements`). AI polish / AI check (partner `/cv/polish`, `/cv/review`) are paid-plan only; polished content goes through `toPlainContent` (our bullets are strings).
- UI loading: page and list loads use shimmer skeletons (`components/skeletons.tsx`, `Skeleton`); spinners only for actions in progress. Icon tiles are quiet: a neutral square (hairline border, faint fill) where only the icon takes the tone (`IconTile tone=accent|sky|violet|emerald|neutral`); no glossy gradients. Orange is for primary actions, CTAs and paywalls. No upsell banners or cards in the content: proactive upsells are pop-ups from `components/UpgradeNudges.tsx` (`pickNudge`, opens the paywall sheet with its own headline): at most one per app open, on main tabs only, 3 s after load, not in the first day. Free: daily alert limit hit (once a day), premium jobs matched this week (every 3 days), 2 days quiet between them. Paid: renewal reminder 3 days before and on the last day (`renew` reason sells the same plan). Beta: none. Pro → Career only via real limits. Never leave a `transform` on a page wrapper (it breaks `position: fixed` bars); the fade-up animation ends at `transform: none` for that reason.
- Saved jobs: `SavedJob` (user, job); `PUT/DELETE /jobs/:id/save`; feed scope `saved` (newest save first, closed jobs included). Cards and the job page use `SaveButton`/`ShareButton` (`components/jobs/JobActions.tsx`); `useToggleSaved` updates every cached copy optimistically.
- Sharing: in Telegram 8.0+ Share sends a photo message: `POST /jobs/:id/share` → `BotService.prepareJobShare` (savePreparedInlineMessage: JPEG card from `<site>/j/:id/share.jpg`, caption `jobShareCaption`, buttons View job (startapp) / Get free job alerts) → `WebApp.shareMessage`; otherwise the plain link. Shared links are `t.me/<bot>?startapp=job_<id>` (`miniAppJobLink`): they open the bot's Main Mini App (must be set in BotFather) and `SessionGate` routes the start param to `/app/jobs/:id` once per launch. Premium jobs (`JobCardDto.premium`) never name the employer in share text or the bot's shared-job reply, only the employer kind. `<site>/j/:id` is still a public page (`app/j/[id]`, data from `GET /public/jobs/:id`, never how to apply) with a generated preview image (`opengraph-image.tsx`, Geist fonts in `src/assets`). Its buttons open the bot with `?start=job_<id>`; the bot replies with that job (`M.sharedJob`) and pitches alerts to new people. In Telegram, Share opens the chat picker (`t.me/share/url`); text in `lib/share.ts`. Product name for shared text: `APP_NAME` in `lib/config.ts`.
- Fixed UI goes through `components/Portal.tsx` (renders into `<body>`): `StickyFooter`, `Sheet`, the bottom nav. Bottom nav is rendered once by `MiniAppProvider`, shown on `/app`, `/app/jobs`, `/app/cvs`, `/app/plans` only; never render it inside a page. The CV editor keeps Preview | Edit and the score (`ScoreChip`) in one sticky top bar.
- CV personal details: `User.cvContact` ({ name, email, phone, location }), `PUT /me/cv-contact`, `MeDto.cvContact`. The CV flow asks for them once (step 1 of 2, `components/cv/ContactForm.tsx`), then reuses them; edited in Profile → CV details.
- Bot copy lives in `bot.messages.ts` (HTML parse mode, escape user text with `escapeHtml`).
- Tests: vitest, pure functions (`pnpm test`). Typecheck: `pnpm typecheck`.

## Speed

The Mini App signs in from the URL's `tgWebAppData` without waiting for Telegram's script, renders a session cached on the device (`mj:session`, same Telegram user, < 20 h) while a fresh sign-in runs, and `Prefetch` loads the main tabs' data right after. The API gzips responses (`compression`).

## Dev

```
pnpm install
pnpm --filter @ethio/shared build && pnpm --filter @ethio/db build
pnpm dev            # api :4000 (bot polling) + web :3000
```
Mini App buttons need https: run a tunnel (e.g. `cloudflared tunnel --url http://localhost:3000`), set `WEB_APP_URL` to it and add it to `CORS_ORIGINS`. Without Telegram, open http://localhost:3000/app with `NEXT_PUBLIC_DEV_AUTH=true`.
